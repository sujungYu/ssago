# 결정·문서 충돌·미정 사항

## 구현 중 내린 가정 (정책서에 없거나 모호해서 화면 동작만 정함)
1. 알림함은 만들지 않았다. S-02는 알림 링크 도착 화면이며, 대상 상태가 알림 이후 바뀌었으면 최신 상태 안내를 붙여 이동한다.
2. 결제 “결과 확인 중” 상태에서는 새 결제를 만들지 않는다(ERR-PAY-03). 조회(`refreshPayment`)만 허용.
3. 그룹이 종료되면 결제 대기 고객의 승인에 `recheck`(새 그룹 조건)가 붙고, 동의해야 결제할 수 있다. 새 그룹은 먼저 결제한 고객이 기준이 된다.
4. 취소 확정 시 확인한 환불 금액(`expectedRefund`)을 함께 보내 금액이 바뀌었으면 거절(ERR-CAN-01). 화면은 금액·조건 버전이 바뀌면 동의를 초기화한다.
5. 지연 대응의 무료 변경·무료 취소는 요청/취소가 완료될 때 지연 안내가 종결되며, 사용자가 직접 고른 “기다리기”만 선택으로 기록한다.
6. 업체 사유 변경 제안을 거절하면 공제 없는 전액 환불 취소로 처리한다.
7. 취소·일정 변경 버튼은 방문 전(`scheduled`)에만 노출한다(작업 시작 후·후속 방문 취소 정책은 미정).
8. 비교 묶음(같은 작업을 여러 업체에 요청)의 식별 방식과 UI는 미정이라 “다른 업체에도 요청” 버튼으로 같은 묶음 ID를 이어 쓰는 방식으로 가정했다.
9. 예상 총액은 `업체 견적 합계 + 부품 예상 + 내 예상 출장비`이며 “최종 금액 아님”을 항상 병기한다.
10. 요청 가능 날짜 최소값은 오늘+48시간(마감 규칙을 맞추기 위한 임시 값).

## 미정(결정하지 않고 표시만 한 것)
- 새 일정 예약금이 기존보다 적어 남는 금액(`excessUndecided`)의 처리 — 화면에 “아직 정해지지 않았어요”로 안내.
- 결제수단·PG, 로그인 방식, 알림 채널·알림함, 업체 정보 관리 범위, 자동 위치 수집·주소 저장.
- 약관·개인정보 처리방침 실제 문안(법률 검토 전) — `/guide`는 서비스 규칙 요약.
- 리뷰 노출 정책(작성자 마스킹 외), 사진 업로드 저장소 — 목업은 파일명만 보관.
- 승인 경계 시각(마감과 같은 시각 등) — 상태 플래그를 우선해 판단.

## 문서 간 충돌·보정
- 화면 IA는 “알림 연결”을 알림함이 아닌 진입 기능으로 정의 → S-02를 랜딩 화면으로 구현.
- 환불 상태: “처리 요청 접수”와 “실제 반영”을 구분(입금 완료로 단정 금지) → 상태 문구 4종으로 표현.
- 결제 대기 자리: 수용 한도에는 포함, 분담 세대 수에는 불포함 → 목록·상세·재확인 모두 같은 계산.
